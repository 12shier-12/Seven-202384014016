# Triply — Offline-First Trip & Packing Planner

> Final year capstone project. A pure front-end travel planner: day-by-day itineraries, and a
> packing list generated by a rule engine from trip length, party size, activity tags and expected
> temperature. No backend, no account — all data lives in the browser's IndexedDB.

**Live demo**: run `pnpm build` in `week4/` and host the generated `dist/` folder on any static
server (GitHub Pages, Netlify, or a school server).

## Quick start (final build)

Step-by-step instructions for a reviewer are in [RUNNING.md](RUNNING.md) — install Node.js, clone the
repository, then run three commands inside `week4/`.

### Open the prebuilt app (no Node.js required)

The final build is already compiled into `week4/dist/`. On Windows, double-click
`打开项目.bat` — it starts a small local server with Python and opens
<http://localhost:8080/>. Keep the console window open while you use the app.

The app is a PWA, so it also works offline after the first load and can be installed from the
browser's address bar. Data is stored in that browser's IndexedDB.

### Develop or rebuild

Requires Node.js >= 20. Then:

```bash
cd week4
pnpm install      # or npm install
pnpm dev          # http://localhost:5173
pnpm test         # 100 tests
pnpm build        # production build + service worker
pnpm preview      # serve the production build
```

On first launch the app seeds three sample trips (7-day Kyoto, 3-day Chengdu, 2-day Hangzhou) with a
full itinerary, so there is something meaningful to look at without typing anything.

## What the final build does

- **Trips** — CRUD, status labels (upcoming / ongoing / past), budget tracking, cover emoji
- **Itinerary** — one column per day, activity CRUD, reorder, move across days, overlap detection
  that names the conflicting activity, daily subtotals
- **Packing list** — rules match on days, party size, tags and temperature; quantities are
  expressions such as `min(days, 7)` or `ceil(days / 3)`; user edits are stored as overrides and never
  overwritten; grouped by category with progress, copy-as-text, CSV, print
- **Offline** — installable PWA, precached app shell, IndexedDB storage, works with no network
- **Data** — JSON export/import with a schema version, reset to sample data

## Design highlights

1. **The packing list is derived, not merged.** Rules produce suggestions; the user's quantity, packed
   state and deletions are stored as overrides keyed by `${ruleId}:${itemName}`. The list is recomputed
   by a pure function, so there is no "regenerate" button and no three-way-merge bug.
2. **A restricted expression engine instead of `eval`.** Tokenizer → AST → evaluator, whitelisted
   variables (`days`, `travelers`, `minTemp`, `maxTemp`) and functions (`min`, `max`, `ceil`, `floor`,
   `round`, `abs`), with error positions.
3. **Time-conflict detection by interval sweep.** Minute-based intervals, sorted scan with an active
   list, returning conflicting pairs so the UI can name them.

## Tech stack

TypeScript, React 18, Vite, Tailwind CSS, Zustand, Dexie (IndexedDB), React Router, Vitest,
vite-plugin-pwa. No runtime network requests; no backend.
